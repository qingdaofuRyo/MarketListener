# 客户产品与内部管理台

2026-10-01 用户确认的当前方向：产品客户使用8765；管理员、程序员与测试人员使用独立的8766内部管理台。第一阶段为本机开发运行，管理服务只绑定127.0.0.1。独立EXE图形启动器退出当前开发主线，历史源码和已有产物保留作迁移参考。

## 入口与职责

| 入口 | 面向对象 | 当前功能 |
|---|---|---|
| `http://127.0.0.1:8765/` | 产品客户 | 全部/目标行情、K线研究、个人策略、画线、账户分析、期货数据、产业链与F10展示 |
| `http://127.0.0.1:8766/` | 本机内部管理员 | 服务启停/重启、数据生产任务（含每日成交持仓排名增量更新）、通达信手动启动/下载、队列/取消排队、内部日志、数据源盘点、环境诊断与运行设置 |

客户端首页进入全部行情，移除原“后端”导航。旧`/logs/`和`/data-sources/`书签回到客户产品首页。员工管理能力不仅从客户UI移走，生产入口还在服务端拒绝未获授权的管理API；个人策略、画线与账户写入仍属于产品能力。

## 前后端与运行结构

```text
管理台前端 desktop/admin-web ──HTTP──> 内部管理服务 :8766
                                           │
                                  有限操作 + 服务凭据
                                           │
客户前端 desktop/web ──产品API──────> 客户运行服务 :8765
                                           │
                                  行情/个人数据与既有任务队列
```

两个前端有各自的入口、资源、构建与职责。管理台使用独立的原生ES模块/CSS前端项目，避免为轻量控制界面引入新的桌面运行时；客户产品继续使用Vue/TypeScript。管理前端构建到`admin_web_dist`，客户构建到`web_dist`，生成目录均被Git忽略；两个服务只提供各自的前端资源。

管理服务的实现为`market_monitor.web_admin`，不连接行情Catalog、不扫描K线。它监督自己创建的客户进程，并把有限的数据操作转发给客户运行服务内的既有串行队列，保持现有DuckDB/数据操作协调方式。用户点击停止客户服务后，8766管理台仍然在线。

## 管理边界

- 管理服务只允许本机连接，并校验Host；修改请求需来自管理页的Origin并带本次会话凭据。
- 客户服务的生产入口`create_customer_web_app`保护`/api/operations`、`/api/logs`、详细`/api/health`、`/api/data-sources`、通达信检查报告、内部进程诊断及平台迁移接口。管理服务与客户服务之间另用服务端凭据；它不会被返回给任一前端。
- 运行记录、隔离区、存储分区、容量/新鲜度等技术面板和原始存储浏览接口也只供管理台使用；客户数据页保留业务指标、F10和产业链查看。旧个人面板引用内部指标时不再展示，历史偏好保留。
- 客户的业务POST/PUT不被一律归入管理员功能。策略定义、指标请求、个人画线和账户资料继续走产品API。
- 现有测试/集成适配器`create_web_app`保留兼容；真实CLI服务使用受保护的客户工厂。不要把兼容工厂用作新的部署入口。
- 端口隔离和CORS不是员工身份系统。第一阶段显示“本机管理员”，没有伪装成已经实现的多员工登录或角色切换。

端口属于浏览器Origin的一部分，两个页面因此属于不同Origin；浏览器管理页仅调用自身管理API，再由服务端转发有限操作，避免给客户页面开放管理跨域凭据。[FastAPI CORS说明](https://fastapi.tiangolo.com/tutorial/cors/)。团队阶段的角色授权必须覆盖每次请求，按能力和数据归属执行。[OWASP授权说明](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)。

## 快捷启动

`scripts/start_marketlistener.py`负责首次启动或识别/复用8766管理服务。两个快捷入口使用同一个后台引导流程，不需要打包图形EXE：

- **MarketListener 管理台**：准备管理服务，打开8766网页。管理服务按偏好启动客户服务。
- **MarketListener 客户端**：准备管理服务，启动或复用客户服务，等待就绪后打开8765网页。
- **系统登录后台启动**：管理台设置中的选项登记本项目`MarketListenerServices`启动项；只准备后台服务，不打开浏览器。
- **登录与解锁恢复**：`powershell -ExecutionPolicy Bypass -File scripts\install_web_startup_recovery.ps1`登记当前用户隐藏计划任务，登录或解锁后延迟检查两服务，失败有限重试；同一启动锁避免与已有启动项重复创建服务。先加`-WhatIf`可查看任务配置。私有启动结果记录在`data_control/logs/web-startup-watchdog.jsonl`。

Windows执行一次`scripts/create_web_shortcuts.ps1 -Desktop`即可生成两个桌面快捷方式，目标为项目锁定Python后台运行时和引导脚本，用户无需输入终端命令。未指定`-Desktop`时生成到被忽略的`artifacts/launch/`。

开发环境首次准备时分别构建两个前端：

```powershell
# 客户产品（需已安装其锁定依赖）
cd desktop/web
npm run build
# 内部管理台（构建不安装新的依赖）
cd ../admin-web
npm run build
```

首次引导发现管理前端未构建时可执行其轻量构建；客户前端未构建时提供明确的网页启动错误结果，不把API就绪冒充客户端可用。POSIX数据生产机可用`sh scripts/start_marketlistener.sh --target admin|client`，仍只有网页UI。

浏览器自身不能唤起已停止的本地Python服务；Windows用户登录自启或运行`desktop\.venv\Scripts\python scripts\start_marketlistener.py --target none`后，本机浏览器直接打开`http://127.0.0.1:8766/`即可进入管理台，无需口令。页面通过同源POST自动建立有时限的本机会话；Cookie、Origin、Host及写入CSRF检查继续生效。会话过期或服务重启后由页面自动恢复。管理服务只绑定回环地址。关闭浏览器只关闭页面，后台服务继续运行；管理台的“关闭管理服务”会停止它拥有的客户服务。旧`--show-login-code`参数仅返回取消口令的说明，不再读取凭据。

系统登录后台启动使用当前Windows用户的`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\MarketListenerServices`，在该用户登录后启动服务并立即检查待补盘后任务；若电脑开机但该用户尚未登录，则不会运行。启用选项不改变数据质量门：周末完整批次可按已核验检查点与原文件覆盖跳过，失败或不确定的扩展市场批次继续对账、重试。

## 资源与进程归属

- 客户服务默认继续自动更新非F10数据，包括最近已结束交易日的成交持仓排名；已有来源覆盖的交易所不重复下载，最新排名任务排在期货结构重建之前。大商所增量批次仍需雷电模拟器保持其官网排名页已打开；若浏览器上下文不可用，任务记录部分失败，其它交易所独立继续。
- 管理台提供“启动后自动更新”和“后台低优先级”选项。后台优先级降低CPU调度优先级，并为支持的数学库设置保守线程预算；它不是磁盘吞吐限制，也不能保证所有前台负载都不受影响。
- 总览显示客户服务进程CPU/内存采样，指标明确不包括采集子进程。暂时未能采样时保留未知，而不是零。
- Windows虚拟环境启动会有Python重定向器子进程；停止操作针对本管理台实际创建的进程树，不按8765占用PID盲目终止程序。发现其他启动方式管理的现有服务时可复用，但停/重启保持禁用。
- 日志只读取固定白名单文件的最近64KiB；页面隐藏时停止轮询，正常轮询周期4秒。管理页不绘制持续的CPU密集动画。

## 团队部署的下一阶段

| 身份 | 需要建立的权限 |
|---|---|
| 平台管理员 | 平台服务与生产任务、数据源治理、账号/角色、发布审计 |
| 开发人员 | 环境/API/异常诊断、开发环境操作；生产数据变更按单独授权 |
| 测试人员 | 测试环境、验证任务与报告、回归证据；无默认生产发布权限 |
| 产品客户 | 购买/授权的产品功能，以及本人研究资料；无平台管理接口权限 |

上述员工多账号权限尚未部署。本机客户个人资料仍遵循当前单机存储边界；在真实多客户部署前须实现身份与客户资料归属校验。团队内网或公网阶段还需HTTPS、会话管理、逐请求授权、审计和验证，不能直接将本机服务绑定到0.0.0.0作为交付。

## 迁移与回退

旧的`MarketListener_Serve`计划任务直接运行`serve.cmd`，可能抢先占用客户端口。迁移时核对其动作属于本项目后停用该旧启动任务，避免和管理服务重复启动。F10等独立任务不因该迁移自动停用。旧图形启动器可正常退出，历史文件不必删除。

源码与配置修改不会改动行情/个人数据库。新配置和日志放在`data_control/state`、`data_control/logs`；快捷图标与构建产物放在忽略目录。功能/权限回退应通过Git版本操作并同步运行入口，不强制修改现有数据包或数据源事实。

## 当前验证（2026-10-01）

49项后端测试、15项浏览器场景、Ruff、受影响ESLint、两个前端构建与`git diff --check`通过。Windows真实有界生命周期验证采用临时数据目录和空闲端口：客户服务启动、授权请求可用、停止后其Python重定向器及子进程均退出。现行管理服务已从8766实际启动客户服务8765，两页可访问，客户进程优先级为BelowNormal；正常非F10更新已排队，未启动通达信界面下载。

管理服务空闲2秒CPU采样为0%，工作集约50.7MiB；该值是本次观察，不是全负载性能承诺。旧Tk美化预览曾因Configure尺寸循环占满一个核心，已关闭并将未交付草稿保存到忽略目录；本次实际运行使用网页方案。
