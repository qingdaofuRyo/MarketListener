# 期货官方交易乘数与名义规模覆盖

## 业务口径

期货合约名义持仓规模使用：

```text
结算价 × 交易所单边持仓量 × 官方合约乘数
```

它与沉淀资金分开。名义规模不乘保证金率或双边系数；沉淀资金继续要求精确交易日保证金率。`quoteUnit`用于注明来源合约规格的报价单位，不能把报价单位或价格尺度当成另一份乘数。

官方乘数注册表位于`desktop/src/market_monitor/config/futures_official_multipliers.json`，由`futures_official_multipliers.py`校验交易所域名、来源SHA-256、获取时间、有效日期、乘数正值和区间重叠。新增历史区间必须保留官网原始文件/响应、哈希、发布时间或生效日证据和解析版本；没有证据时返回缺少官方乘数，不前值填充或从相邻交易日猜测。

## 当前重建状态

历史公式版本`futures-structure-notional-official-v4`独立写Gold和每日输入覆盖表，字段区分缺结算价、缺持仓量、缺官方乘数，并记录受影响品种键和合约。它重建到2026-09-24，写入9,128条可计算品种日记录，但DCE/GFEX缺乘数导致没有完整全市场基准。最新页面默认使用新增`official-v5`直连官方日行情Gold，可切换回TDX v3；v4历史诊断保留，不覆盖任何旧版本。

截至2026-09-24，761个有效月份合约输入中271个未能解析官方乘数、涉及28个品种。DCE/GFEX官方有效区间补齐并按官方修订日核验前，历史断点不应被描述为完全修复；SHFE/CZCE当前登记区间的历史变更审计也未封板。

## R4 官方逐日行情独立版本（2026-09-27）

新增`futures-structure-notional-official-v5`从Catalog中的交易所官方逐合约日行情计算，不读TDX Silver、不回退到v3/v4的输入；结算价、单边持仓或乘数任一缺失时该合约不计入，整日保留`PARTIAL`。支持来源由`source=official`选择，原TDX版本通过`source=tdx`独立查询。

名义规模接口与官方持仓量、成交量共用统一日历，保留每个交易日六所采集覆盖。只要仍有可计算品种，最新可计算日可作为临时Top40参考基准，但响应必须标记该基准日质量为`PARTIAL`；这只为已计算品种折线提供排序，不能据此画全市场总额或完整面积。每个缺口日市场总量和堆叠面积留空，已核验品种绝对值线可以保留。

本轮只验证了fixture和官网单日探测结果，没有启动一年回补。当前注册表仍缺DCE/GFEX完整乘数区间，`official-v5`的历史覆盖必须在真实日行情回填和有效期乘数质量门通过后重新计算；不可将代码存在或单日样本外推为历史覆盖完成。
